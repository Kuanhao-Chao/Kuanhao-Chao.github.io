## The question this lesson answers

A locus is significant and a hundred variants in it are significant, because they are all in
LD with whatever is actually doing the work. Fine-mapping narrows that to a short list. How
much should you believe the list?

The machinery — approximate Bayes factors, posterior inclusion probabilities, credible sets —
is derived in
[Bayesian Fine-mapping](/deep_dives/statgen-bayesian-fine-mapping/) and is not repeated here.
This lesson is about running it and reading it, and in particular about the assumption the
output is silent on.

<Callout variant="intuition">

A credible set answers a **conditional** question: *given that exactly one of these variants
is causal, which are the candidates?* Everything reported — the posterior inclusion
probabilities, the coverage, the purity — is computed inside that conditional.

So if the causal variant is not among the ones supplied, the method does not report failure.
It reports the best answer available under a premise that is false, and it reports it with
exactly the same confidence it would have shown had the premise held. That is the failure
mode this lesson is built around, because the two standard diagnostics cannot see it.

</Callout>

## The same locus, run twice

<WorkedExample
  title="A credible set that excludes the causal variant and reports nothing wrong"
  given={[
    { label: 'Region', value: '8 variants, causal at position 4' },
    { label: 'z-scores', value: '2.1, 4.6, 6.2, 6.5, 6.2, 4.6, 2.4, 1.8' },
    { label: 'Null prior', value: 'π₀ = 0.05, uniform over the rest' },
    { label: 'Target coverage', value: '95%' },
  ]}
  verifiedBy="src/lib/deepDiveExamples.test.ts"
>

**Step 1 — with everything present.** Running the standard machinery over all eight variants,
with the posterior normalised against an explicit $\pi_0 = 0.05$, gives

$$
\text{PIP} = (0.000000,\; 0.000021,\; 0.114882,\; \mathbf{0.770194},\; 0.114882,\; 0.000021,\; 0.000000,\; 0.000000) .
$$

The causal variant takes 0.770194 and its two immediate neighbours 0.114882 each. The 95%
credible set is those three, with **coverage 0.999959** and **purity 0.7000** — the smallest
correlation between any two members. That is an honest and useful result: the signal is
localised to three variants and the data cannot go further at this sample size.

**Step 2 — now drop the causal variant.** Not maliciously: it failed the imputation-quality
filter from [Arrays & Imputation](/deep_dives/gwas-arrays-imputation/), or it is absent from
the reference panel, or it is an indel the pipeline skipped. Everything else is identical. Re-running over the remaining seven:

$$
\text{PIP} = (0.000000,\; 0.000089,\; \mathbf{0.499911},\; \mathbf{0.499911},\; 0.000089,\; 0.000000,\; 0.000000) .
$$

The two flanking tags now split the posterior evenly. The 95% credible set is those two, with
**coverage 0.999821** and **purity 0.7000**.

**Step 3 — compare the two reports.** Coverage: 0.999959 against 0.999821. Purity: 0.7000
against 0.7000. Set size: three against **two**.

By the number a reader weighs most, the second run is the *better* result — a set of two
rather than three, at identical purity. Coverage is not quite equal, and it moves the wrong
way for the story a tool would tell: 0.999821 against 0.999959, a difference four decimal
places down and far too small to flag anything. It is also the run whose credible set does not
contain the causal variant, and there is no diagnostic in the output that distinguishes them.

**Step 4 — what would have caught it.** Nothing downstream. The check has to happen upstream:
confirm that the region's variants were not thinned by an INFO filter, that the reference
panel covers the region's frequency spectrum, and that indels and multi-allelic sites were
not silently dropped. A credible set is only as complete as the candidate list it was given,
and that list is assembled in
[Arrays & Imputation](/deep_dives/gwas-arrays-imputation/) and
[Quality Control](/deep_dives/gwas-quality-control/), six and five lessons earlier.

</WorkedExample>

## What fine-mapping needs to work

**In-sample LD, not a reference panel.** Clumping can tolerate an approximate LD matrix
because it only has to decide which variants are roughly the same signal. Fine-mapping is
trying to separate variants that are *nearly identical*, and a small error in the correlation
between two candidates moves the posterior between them. The previous lesson's arithmetic is
the reason: $r^2$ estimated from the wrong population is not slightly wrong, it is a
different number. Where in-sample LD is unavailable, the honest report is a larger credible
set, not a confident small one <Citation id="benner2016finemap" />.

**A model that allows more than one causal variant.** The single-causal-variant assumption is
frequently false, and its signature is recognisable: after conditioning on the lead variant,
a secondary signal remains. Methods built on a sum of single effects
<Citation id="wang2020susie" /> return several credible sets per locus for exactly this
reason, and a locus reported with one set by a single-effect method and three by SuSiE is
usually the latter being right.

**Summary statistics that match the LD.** If the effect estimates come from a meta-analysis
across cohorts with different LD structures, no single LD matrix describes them, and
fine-mapping on the meta-analysed statistics is not well defined however good the panel is.
This is a common and under-reported problem in consortium papers.

## From a variant to a gene

A credible set names positions. It does not name genes, and the two steps most often used to
bridge that gap are both weaker than they look.

**Nearest gene** is right often enough to be tempting and wrong often enough to be dangerous.
Regulatory variants act at distance, through chromatin contacts that ignore linear order. The
[chromatin playground](/chromatin/) is where that geometry is visible: cohesin extrudes a loop
until it meets two convergent CTCF sites, and a variant and its target gene can sit at opposite
anchors of the same loop while a nearer gene sits outside it.

**Colocalisation** with an expression QTL <Citation id="giambartolomei2014coloc" /> asks
whether the trait signal and the expression signal share a causal variant, which is a
sharper question than "is there an eQTL nearby" — and it inherits every limitation above,
since it is fine-mapping run twice and compared. A colocalisation computed on mismatched LD
is as unreliable as the fine-mapping underneath it
<Citation id="hormozdiari2016ecaviar" />.

**Integrated scores** <Citation id="mountjoy2021l2g" /> combine distance, colocalisation,
chromatin data and functional prediction into a ranking. They are the best available
automated answer and are still a ranking, not an identification.

<Callout variant="warning" title="Fine-mapping transfers worse than association does">

The *direction* of an effect at an already-discovered locus is often concordant across
populations, because the causal variant is usually present in both. Whether the locus is
**detectable** at all is not: the previous lesson took one tag from $r^2 = 0.64$ to $0.078$
between two populations at identical allele frequencies, an 8.16-fold penalty in the sample
size needed to see through it. So even association transfers less well than it is usually
credited with.
Fine-mapping does not, for the reason lesson 7 made concrete: the credible set depends on
$r^2$ among candidates, and $r^2$ is population-specific.

A credible set from a European cohort is a statement about European haplotypes. Applying it
elsewhere — or fine-mapping a multi-ancestry meta-analysis with a European panel — produces
confident, well-covered, high-purity nonsense <Citation id="martin2019" />. The upside is
that multi-ancestry data is genuinely *more* informative here than more of the same
ancestry <Citation id="tgp2015" />: different LD structures break different ties, and a
variant causal in both populations is the one that stays significant in both.

</Callout>

## Exercises

<Exercise n={1} title="Reading three reports" difficulty="warm-up">

Three loci come back from the same pipeline:

- Locus A: 2 variants, coverage 0.96, purity 0.98.
- Locus B: 41 variants, coverage 0.95, purity 0.91.
- Locus C: 3 variants, coverage 0.95, purity 0.12.

(a) Which is the most useful result?

(b) What does locus B's report mean?

(c) What is wrong with locus C?

<div slot="solution">

**(a)** Locus A. Two candidates in near-perfect LD is the best outcome available from
statistics alone: the data have localised the signal as far as they can, and the remaining
ambiguity is a property of the region rather than of the study.

**(b)** That the region is large and the LD is extensive, so 41 variants are needed to reach
95%. It is not a failure — it is an accurate report that this locus is not resolvable at this
sample size. Reporting the lead variant as "the" variant would be the failure.

**(c)** A purity of 0.12 means two members of the set are essentially uncorrelated, which a
single-causal-variant model should never produce: if only one variant is causal, everything
sharing its posterior must share its LD. The likely truth is **two causal variants** being
forced into one set. SuSiE would report them as separate credible sets, and tools drop sets
below a purity of 0.5 for this reason.

</div>
</Exercise>

<Exercise n={2} title="A tighter set after a filter change" difficulty="core">

A team re-runs fine-mapping after tightening their imputation INFO filter from 0.3 to 0.8.
Several loci come back with smaller credible sets. The team reports improved resolution.

(a) Is that a reasonable interpretation?

(b) What is the alternative explanation?

(c) How would you distinguish them?

<div slot="solution">

**(a)** Partly. A tighter INFO filter does remove poorly-imputed variants whose uncertain
dosages genuinely blur the posterior, so some of the improvement can be real.

**(b)** That the filter removed candidate variants, including causal ones — exactly the
worked example. A credible set drawn from a smaller candidate list is smaller almost
mechanically, and its coverage and purity are unchanged because both are computed within
whatever list was supplied.

**(c)** Check whether the lead variant of each shrunken set changed. If the set merely lost
peripheral members and kept the same top variant, the resolution claim is plausible. If the
top variant moved, a candidate carrying substantial posterior was removed, and the new set is
answering a different question. Also check how many variants the filter removed *inside* each
credible region specifically — a genome-wide count will not show it, because the regions that
matter are a tiny fraction of the genome.

</div>
</Exercise>

<Exercise n={3} title="One locus, two ancestries" difficulty="stretch">

A locus is genome-wide significant in both a European and an East Asian cohort with similar
effect sizes. Fine-mapped separately, the European credible set has 6 variants and the East
Asian 4, and they share exactly one variant.

(a) Is this a contradiction?

(b) What does the shared variant suggest?

(c) The team proposes meta-analysing the two and fine-mapping the combined statistics with a
European panel. Comment.

<div slot="solution">

**(a)** No — it is the expected result, and a useful one. The two sets are answering the same
question under different LD structures. A variant that is indistinguishable from four others
in Europeans may be well separated in East Asians because recombination has broken that
haplotype differently, and vice versa.

**(b)** That it is the strongest candidate available. A single variant appearing in both sets
is supported under two different correlation structures, which is much stronger evidence than
a high posterior under one. This is the mechanism by which multi-ancestry data improves
fine-mapping resolution rather than merely adding samples.

**(c)** It would discard the advantage and add a bias. The gain above comes from the two
populations having *different* LD; meta-analysing pools the effect estimates while a single
panel imposes one LD structure on statistics that were generated under two, so the model is
misspecified for at least one cohort — and a European panel makes it the East Asian cohort.
The correct approach is to fine-map each cohort with its own in-sample LD and intersect, or
to use a method that takes per-cohort LD matrices explicitly. The intersection is what
question (b) already exploited.

</div>
</Exercise>

## Summary

- **A credible set is conditional on the causal variant being among the candidates**, and
  when it is not, the method reports the best answer under a false premise with undiminished
  confidence.
- **Coverage and purity cannot detect that failure.** Dropping the causal variant took the set
  from three members at coverage 0.999959 to two at 0.999821, purity 0.7000 both times — a
  tighter, better-looking, wrong answer.
- **The check is upstream.** Confirm the region's variants were not thinned by an
  imputation-quality filter or missing from the panel before believing any credible set.
- **Fine-mapping needs in-sample LD** where clumping tolerates a panel, because it is
  separating variants that are nearly identical and $r^2$ is population-specific.
- **A low-purity set is usually two causal variants**, not one uncertain signal, and a
  multi-effect method will say so.
- **Multi-ancestry data helps here more than more of the same ancestry**, because different
  LD structures break different ties — but only if each cohort is fine-mapped with its own
  LD rather than pooled under one panel.
